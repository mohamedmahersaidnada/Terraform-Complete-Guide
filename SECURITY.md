# Security policy

Do not post credentials, state, plan files or private infrastructure details in public issues. Use the repository's GitHub private vulnerability reporting when enabled. If unavailable, contact the maintainer through the contact method listed on their GitHub profile to arrange private disclosure before sending sensitive details. No private reporting address is asserted here.

For exposed credentials, revoke or rotate them first, investigate provider audit logs, restrict affected artifacts, and coordinate repository history remediation. Removing a file from the latest commit does not revoke credentials or erase history.

Examples are educational. Static validation does not establish production suitability. Report ordinary documentation errors through issues with a sanitized reproduction. Maintainers review the default branch; no historical release security support is promised.
